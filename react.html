Qu'est-ce que React ?

React est une bibliothèque JavaScript (pas un framework complet) créée par Meta en 2013 pour construire des interfaces utilisateurs. Elle repose sur trois idées :

  • Composants : l'UI est découpée en blocs réutilisables
  • Déclaratif : tu décris ce que l'UI doit afficher, React s'occupe du comment
  • État → rendu : quand l'état change, l'UI se met à jour automatiquement
📌 React n'est pas un framework React ne gère ni le routing, ni les requêtes HTTP, ni le state global, ni le SSR. C'est pour ça qu'on l'associe à d'autres outils (React Router, TanStack Query, Redux/Zustand, Next.js…).

Installation

Trois grandes façons de démarrer un projet React en 2024–2025 :

1. Vite (recommandé pour SPA)

Le standard actuel. Rapide, léger, configuration minimale.

# Prérequis : Node.js 18+
npm create vite@latest mon-app -- --template react
cd mon-app
npm install
npm run dev

Variantes : --template react-ts pour TypeScript (recommandé en prod).

2. Next.js (recommandé pour sites / SEO)

Framework complet par-dessus React : routing, SSR, API routes, optimisation d'images.

npx create-next-app@latest mon-app
cd mon-app
npm run dev

3. React pur avec CDN (pour apprendre / prototyper)

Utile pour tester React sans build, mais pas pour un vrai projet.

<script src="https://unpkg.com/react@18/umd/react.development.js"></script>
<script src="https://unpkg.com/react-dom@18/umd/react-dom.development.js"></script>
<script src="https://unpkg.com/@babel/standalone/babel.min.js"></script>
✅ Choix senior
  • SPA dashboard / app interne → Vite + TypeScript
  • Site public avec SEO → Next.js (App Router)
  • Mobile → React Native / Expo
Évite Create React App (CRA) : déprécié depuis 2023.

JSX & composants

JSX = HTML dans le JS. Ce n'est pas du HTML, c'est du sucre syntaxique transformé en appels React.createElement.

Composant fonction (standard moderne)

function Bienvenue({ nom }) {
  return <h1>Bonjour, {nom} !</h1>;
}

// Usage :
<Bienvenue nom="Alice" />

Composant avec état

import { useState } from 'react';

function Compteur() {
  const [count, setCount] = useState(0);
  return (
    <button onClick={() => setCount(c => c + 1)}>
      Cliqué {count} fois
    </button>
  );
}
⚠️ Règles JSX
  • className au lieu de class
  • htmlFor au lieu de for
  • Une seule racine : <>...</> (Fragment)
  • Expressions JS : {condition && <X />}
  • Événements camelCase : onClick, onChange

Hooks essentiels

Les hooks permettent d'utiliser l'état et le cycle de vie dans des composants fonctions.

useState — état local

const [user, setUser] = useState(null);
// Mise à jour fonctionnelle (si dépend d'ancienne valeur) :
setUser(prev => ({ ...prev, name: 'Alice' }));

useEffect — effets de bord

useEffect(() => {
  const controller = new AbortController();

  fetch('/api/users', { signal: controller.signal })
    .then(r => r.json())
    .then(setUsers)
    .catch(err => {
      if (err.name !== 'AbortError') console.error(err);
    });

  return () => controller.abort(); // cleanup
}, []); // [] = une fois au montage
⚠️ Piège classique Oublier la fonction de cleanup dans useEffect → fuites mémoire, requêtes en double, race conditions en React 18 StrictMode (qui monte deux fois en dev).

useRef — valeur persistante sans re-render

const inputRef = useRef(null);
const renderCount = useRef(0);

useEffect(() => { renderCount.current++; });

// Focus programmatique
<input ref={inputRef} />
inputRef.current?.focus();

useContext — éviter le prop drilling

import { createContext, useContext } from 'react';

const ThemeContext = createContext('dark');

function Button() {
  const theme = useContext(ThemeContext);
  return <button className={theme}>OK</button>;
}

useMemo / useCallback

// useMemo : mémorise une VALEUR calculée
const sorted = useMemo(
  () => items.slice().sort((a, b) => a.nom.localeCompare(b.nom)),
  [items]
);

// useCallback : mémorise une FONCTION
const handleClick = useCallback(() => {
  console.log(id);
}, [id]);
❌ Ne pas abuser Mémoïser partout est une anti-pratique. Commence sans, mesure avec le React DevTools Profiler, ajoute useMemo/useCallback seulement là où c'est mesuré.

Custom hook

function useLocalStorage(key, initial) {
  const [value, setValue] = useState(() => {
    const item = localStorage.getItem(key);
    return item ? JSON.parse(item) : initial;
  });

  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(value));
  }, [key, value]);

  return [value, setValue];
}

// Usage
const [theme, setTheme] = useLocalStorage('theme', 'dark');

Structure de projet senior

Le découpage par feature (domain) est plus maintenable que par type (components / hooks / utils séparés).

src/
├── main.jsx
├── App.jsx
├── components/       → composants génériques (Button, Modal…)
│   └── ui/
├── features/         → un dossier par domaine métier
│   ├── auth/
│   │   ├── AuthForm.jsx
│   │   ├── useAuth.js
│   │   └── api.js
│   └── posts/
│       ├── PostList.jsx
│       ├── PostCard.jsx
│       ├── usePosts.js
│       └── api.js
├── hooks/            → hooks partagés
├── lib/              → utilitaires (formatters, constants)
├── services/         → appels API / clients HTTP
└── styles/
✅ Règle Un composant qui fait plus de 150 lignes = découper. Un fichier qui importe plus de 10 modules = suspect.

Bonnes pratiques senior

1. TypeScript par défaut

React + TS est le standard pro. Les props sont typées, les erreurs détectées à la compilation.

type ButtonProps = {
  label: string;
  onClick: () => void;
  variant?: 'primary' | 'secondary';
};

function Button({ label, onClick, variant = 'primary' }: ButtonProps) {
  return <button className={variant} onClick={onClick}>{label}</button>;
}

2. Composer plutôt qu'hériter

// ❌ Props en cascade (prop drilling)
<Layout user={user} theme={theme} setTheme={setTheme} notifications={n} />

// ✅ Composition
<Layout>
  <Header user={user} />
  <Content theme={theme} />
  <Notifications items={n} />
</Layout>

3. Gestion d'état : commencer simple

BesoinOutil
État local UIuseState
État partagé peu profonduseContext
État serveur (cache API)TanStack Query / SWR
État global complexeZustand (léger) / Redux Toolkit
URL comme étatReact Router
❌ Anti-pattern Mettre tout dans Redux dès le départ. 80 % des apps n'en ont pas besoin. L'état serveur (données API) ne devrait pas être dans Redux — utilise TanStack Query.

4. Séparer la logique de l'UI

// ❌ Composant fourre-tout
function UserList() {
  const [users, setUsers] = useState([]);
  useEffect(() => { fetch('/users').then(r => r.json()).then(setUsers); }, []);
  // ... 80 lignes de JSX
}

// ✅ Hook dédié + composant présentationnel
function useUsers() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    fetch('/users')
      .then(r => r.json())
      .then(setUsers)
      .catch(setError)
      .finally(() => setLoading(false));
  }, []);

  return { users, loading, error };
}

function UserList() {
  const { users, loading, error } = useUsers();
  if (loading) return <p>Chargement…</p>;
  if (error) return <p>Erreur</p>;
  return users.map(u => <UserCard key={u.id} user={u} />);
}

5. Accessibilité (a11y) dès le début

  • Utilise des éléments sémantiques : <button>, <nav>, <main>
  • Chaque <img> a un alt
  • Chaque <input> a un <label htmlFor> ou aria-label
  • Gère le focus dans les modales (<dialog> ou React Aria)
  • Teste au clavier uniquement (Tab, Entrée, Échap)

6. Clés stables dans les listes

// ❌ index : bug quand la liste est réordonnée
items.map((item, i) => <Row key={i} />)

// ✅ ID métier
items.map(item => <Row key={item.id} />)

7. Gestion d'erreurs avec Error Boundary

class ErrorBoundary extends React.Component {
  state = { hasError: false };
  static getDerivedStateFromError() { return { hasError: true }; }
  componentDidCatch(error, info) { console.error(error, info); }
  render() {
    if (this.state.hasError) return <h1>Une erreur est survenue.</h1>;
    return this.props.children;
  }
}

8. Tests : Vitest + React Testing Library

import { render, screen, fireEvent } from '@testing-library/react';
import { test, expect } from 'vitest';
import Compteur from './Compteur';

test('incrémente au clic', () => {
  render(<Compteur />);
  fireEvent.click(screen.getByRole('button'));
  expect(screen.getByText(/1 fois/)).toBeInTheDocument();
});
✅ Tester le comportement, pas l'implémentation Teste ce que voit l'utilisateur (rôles, texte) — pas les détails internes (noms de state, classes CSS).

9. ESLint + Prettier + conventions

npm install -D eslint prettier eslint-plugin-react-hooks

# eslint.config.js
export default [
  {
    rules: {
      'react-hooks/rules-of-hooks': 'error',
      'react-hooks/exhaustive-deps': 'warn',

Conventions de nommage :

  • Composants : PascalCase (UserCard.jsx)
  • Hooks : useXxx (useAuth.js)
  • Fichiers utils : camelCase (formatDate.js)
  • Constantes : UPPER_SNAKE

10. Ne pas stocker de données dérivées

// ❌ Full name stocké dans le state
const [user, setUser] = useState({ first: '', last: '', full: '' });

// ✅ Dérivé au rendu
const full = `${user.first} ${user.last}`;

Performance

  • Code splitting : React.lazy(() => import('./Page')) + <Suspense>
  • Virtualisation des longues listes : react-window / @tanstack/react-virtual
  • Images optimisées : loading="lazy", formats WebP/AVIF, srcset
  • Mesurer avant d'optimiser : React DevTools Profiler, Lighthouse
  • Éviter les re-renders inutiles : composants petits, state proche de l'usage
  • Ne pas mémoïser par défaut : React.memo et useMemo coûtent aussi

Avantages & limites honnêtes

✅ Avantages

  • Écosystème immense : librairies pour tout, communauté énorme, embauche facile
  • Composants réutilisables : UI modulaire, testable
  • Déclaratif : code plus prévisible que le DOM impératif
  • React Native : mêmes concepts pour le mobile
  • Meta + communauté : évolution stable, outillage mature (DevTools, Vite, Next)
  • Hiring : compétence très demandée

❌ Limites

  • Ce n'est pas un framework : il faut assembler routing, state, data fetching — paradoxe du choix
  • Churn : l'écosystème bouge vite (CRA → Vite → Next App Router…), fatigue d'apprentissage
  • Boilerplate : sans TypeScript + outils, ça devient vite le bazar
  • Performance à gérer : re-renders à surveiller sur grosses apps (mais pas pire que les concurrents)
  • SEO : nécessite SSR/SSG (Next.js) pour les sites publics
  • Overkill pour un site vitrine simple — HTML/CSS suffit
🎯 Verdict senior React est un excellent choix pour des apps avec beaucoup d'interactivité et une équipe. Pour un site vitrine ou un blog, Astro ou du HTML statique sont plus simples et plus rapides. Pour du full-stack TS, Next.js est le choix par défaut en 2025.
