Qu'est-ce que React ?

React est une bibliothèque JavaScript (pas un framework complet) créée par Meta en 2013 pour construire des interfaces utilisateurs. Trois idées centrales :

  • Composants : l'UI est découpée en blocs réutilisables
  • Déclaratif : tu décris ce que l'UI doit afficher, React fait le comment
  • État → rendu : quand l'état change, l'UI se met à jour automatiquement

📌 React n'est pas un framework React ne gère ni le routing, ni les requêtes HTTP, ni le state global, ni le SSR. C'est pour ça qu'on l'associe à React Router, TanStack Query, Zustand, Next.js…

Installation

1. Vite (recommandé pour SPA)

npm create vite@latest mon-app -- --template react
cd mon-app
npm install
npm run dev

Variante TypeScript : --template react-ts (recommandée en prod).

2. Next.js (recommandé pour sites / SEO)

npx create-next-app@latest mon-app
cd mon-app
npm run dev
✅ Choix senior
  • SPA dashboard / app interne → Vite + TypeScript
  • Site public avec SEO → Next.js (App Router)
  • Mobile → React Native / Expo
Évite Create React App : déprécié depuis 2023.

JSX & composants

Composant fonction (standard moderne)

function Bienvenue({ nom }) {
  return <h1>Bonjour, {nom} !</h1>;
}

<Bienvenue nom="Alice" />

Composant avec état

import { useState } from 'react';

function Compteur() {
  const [count, setCount] = useState(0);
  return (
    <button onClick={() => setCount(c => c + 1)}>
      Cliqué {count} fois
    </button>
  );
}
⚠️ Règles JSX
  • className au lieu de class
  • htmlFor au lieu de for
  • Une seule racine : <>...</>
  • Expressions JS : {condition && <X />}
  • Événements camelCase : onClick, onChange

Hooks essentiels

useState — état local

const [user, setUser] = useState(null);
setUser(prev => ({ ...prev, name: 'Alice' }));

useEffect — effets de bord

useEffect(() => {
  const controller = new AbortController();
  fetch('/api/users', { signal: controller.signal })
    .then(r => r.json())
    .then(setUsers)
    .catch(err => {
      if (err.name !== 'AbortError') console.error(err);
    });
  return () => controller.abort();
}, []);
⚠️ Piège classique Oublier le cleanup dans useEffect → fuites mémoire, requêtes en double, race conditions.

useRef, useContext, useMemo

const inputRef = useRef(null);
<input ref={inputRef} />
inputRef.current?.focus();

const ThemeContext = createContext('dark');
const theme = useContext(ThemeContext);

const sorted = useMemo(
  () => items.slice().sort((a, b) => a.nom.localeCompare(b.nom)),
  [items]
);
❌ Ne pas abuser Mémoïser partout est une anti-pratique. Commence sans, mesure avec le Profiler, ajoute useMemo/useCallback seulement où c'est mesuré.

Bonnes pratiques senior

1. TypeScript par défaut

type ButtonProps = {
  label: string;
  onClick: () => void;
  variant?: 'primary' | 'secondary';
};

function Button({ label, onClick, variant = 'primary' }: ButtonProps) {
  return <button className={variant} onClick={onClick}>{label}</button>;
}

2. Composer plutôt qu'hériter

// ❌ Prop drilling
<Layout user={user} theme={theme} setTheme={setTheme} />

// ✅ Composition
<Layout>
  <Header user={user} />
  <Content theme={theme} />
</Layout>

3. Gestion d'état : commencer simple

BesoinOutil
État local UIuseState
État partagé peu profonduseContext
État serveur (cache API)TanStack Query / SWR
État global complexeZustand / Redux Toolkit
URL comme étatReact Router
❌ Anti-pattern Mettre tout dans Redux dès le départ. 80 % des apps n'en ont pas besoin. L'état serveur (données API) ne devrait pas être dans Redux.

4. Séparer la logique de l'UI (custom hooks)

function useUsers() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    fetch('/users')
      .then(r => r.json())
      .then(setUsers)
      .catch(setError)
      .finally(() => setLoading(false));
  }, []);

  return { users, loading, error };
}

function UserList() {
  const { users, loading, error } = useUsers();
  if (loading) return <p>Chargement…</p>;
  if (error) return <p>Erreur</p>;
  return users.map(u => <UserCard key={u.id} user={u} />);
}

5. Accessibilité (a11y) dès le début

  • Éléments sémantiques : <button>, <nav>, <main>
  • Chaque <img> a un alt
  • Chaque <input> a un <label htmlFor>
  • Gère le focus dans les modales
  • Teste au clavier uniquement (Tab, Entrée, Échap)

6. Clés stables dans les listes

// ❌ index : bug quand la liste est réordonnée
items.map((item, i) => <Row key={i} />)

// ✅ ID métier
items.map(item => <Row key={item.id} />)

7. Tests : Vitest + React Testing Library

import { render, screen, fireEvent } from '@testing-library/react';
import { test, expect } from 'vitest';

test('incrémente au clic', () => {
  render(<Compteur />);
  fireEvent.click(screen.getByRole('button'));
  expect(screen.getByText(/1 fois/)).toBeInTheDocument();
});
✅ Tester le comportement, pas l'implémentation Teste ce que voit l'utilisateur (rôles, texte) — pas les détails internes.

Avantages & limites honnêtes

✅ Avantages

  • Écosystème immense : librairies pour tout, communauté énorme
  • Composants réutilisables : UI modulaire, testable
  • Déclaratif : code plus prévisible
  • React Native : mêmes concepts pour le mobile
  • Hiring : compétence très demandée

❌ Limites

  • Ce n'est pas un framework : il faut assembler routing, state, data fetching
  • Churn : l'écosystème bouge vite (CRA → Vite → Next App Router)
  • Boilerplate : sans TypeScript + outils, ça devient vite le bazar
  • SEO : nécessite SSR/SSG pour les sites publics
  • Overkill pour un site vitrine simple
🎯 Verdict senior React est excellent pour des apps avec beaucoup d'interactivité et une équipe. Pour un site vitrine, HTML statique suffit. Pour du full-stack TS, Next.js est le choix par défaut en 2025.
