2. La syntaxe JSX

JSX n'est pas du HTML, c'est du JavaScript qui ressemble à du HTML. Il y a quelques règles strictes :

  • On utilise className au lieu de class.
  • Les balises doivent être fermées (<img />).
  • On ne peut retourner qu'un seul élément parent (utilisez <>...</> si besoin).
function App() {
  const nom = "Alice";
  return (
    <div className="container">
      <h1>Bonjour {nom}</h1>
    </div>
  );
}

3. Les Props (Propriétés)

Les props permettent de faire passer des données d'un composant parent vers un composant enfant. C'est le sens unique de l'information.

// Composant Enfant
function Bouton({ texte, couleur }) {
  return <button style={{ color: couleur }}>{texte}</button>;
}

// Composant Parent
function App() {
  return <Bouton texte="Cliquez-moi" couleur="blue" />;
}
Conseil de Senior

Ne modifiez JAMAIS une prop à l'intérieur du composant enfant. Les props sont en lecture seule. Si le composant doit changer une valeur, elle doit venir de son propre State (chapitre 2).

1. Qu'est-ce que le State ?

Le state est la "mémoire" de votre composant. Contrairement aux variables classiques, quand une variable d'état change, React re-rend automatiquement le composant pour afficher la nouvelle valeur.

2. Le hook useState

import { useState } from 'react';

function Compteur() {
  // count est la valeur, setCount est la fonction pour la modifier
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Vous avez cliqué {count} fois</p>
      <button onClick={() => setCount(count + 1)}>
        Cliquer
      </button>
    </div>
  );
}

3. Mise à jour basée sur l'ancienne valeur

Si votre nouvelle valeur dépend de l'ancienne, utilisez toujours la fonction de rappel.

// ❌ Risqué si clics très rapides
setCount(count + 1);

// ✅ Sûr
setCount(prevCount => prevCount + 1);

1. Le rôle de useEffect

Parfois, on doit faire des choses "en dehors" du rendu de l'interface : appeler une API, manipuler le titre de la page, écouter le redimensionnement de la fenêtre. C'est le rôle de useEffect.

2. Le tableau de dépendances

C'est le deuxième argument de useEffect. Il détermine QUAND l'effet doit s'exécuter.

  • [] (vide) : S'exécute une seule fois, au montage du composant.
  • [valeur] : S'exécute au montage ET à chaque fois que valeur change.
  • Absent : S'exécute à chaque rendu (souvent une erreur).

3. Exemple : Fetch de données

import { useState, useEffect } from 'react';

function Utilisateurs() {
  const [data, setData] = useState([]);

  useEffect(() => {
    async function fetchData() {
      const res = await fetch('https://jsonplaceholder.typicode.com/users');
      const json = await res.json();
      setData(json);
    }
    fetchData();
  }, []); // [] = uniquement au démarrage

  return <ul>{data.map(u => <li key={u.id}>{u.name}</li>)}</ul>;
}
Conseil de Senior

Nettoyez toujours vos effets ! Si vous créez un timer ou un écouteur d'événement dans un useEffect, retournez une fonction de nettoyage (return () => clearInterval(...)) pour éviter les fuites de mémoire.

Inputs Contrôlés vs Non-Contrôlés

En React, on préfère les inputs contrôlés : React est la seule source de vérité pour la valeur de l'input.

function Formulaire() {
  const [email, setEmail] = useState('');

  const handleSubmit = (e) => {
    e.preventDefault(); // Empêche le rechargement de la page
    console.log("Email envoyé :", email);
  };

  return (
    <form onSubmit={handleSubmit}>
      <input 
        type="email" 
        value={email} 
        onChange={(e) => setEmail(e.target.value)} 
      />
      <button type="submit">Envoyer</button>
    </form>
  );
}

Le problème du Prop Drilling

Si un composant tout en bas de l'arbre a besoin d'une donnée du composant tout en haut, on est obligé de faire passer la prop par tous les composants intermédiaires. C'est le "Prop Drilling".

La solution : createContext

import { createContext, useContext } from 'react';

// 1. Créer le contexte
const ThemeContext = createContext(null);

// 2. Fournir la valeur (tout en haut)
function App() {
  return (
    <ThemeContext.Provider value="dark">
      <Page />
    </ThemeContext.Provider>
  );
}

// 3. Consommer la valeur (tout en bas)
function Bouton() {
  const theme = useContext(ThemeContext);
  return <button className={theme}>OK</button>;
}
