Ouvrir le module complet (Théorie, Pièges, Exos)

1. Le Contexte d'Exécution (Execution Context)

Tout code JS s'exécute dans un contexte. Il y a le contexte global (le fichier) et les contextes de fonction. JS lit d'abord tout le code pour allouer la mémoire (phase de création), puis l'exécute (phase d'exécution). C'est ce qui explique le Hoisting.

console.log(maVar); // undefined (et non pas une erreur)
var maVar = "Bonjour";

// Mais avec let et const :
// console.log(maConst); // ReferenceError: Cannot access before initialization
const maConst = "Salut";

Règle : Utilisez toujours const ou let pour éviter les bugs silencieux du Hoisting.

2. La Coercition (Conversion de type)

JavaScript essaie de deviner ce que vous voulez faire quand vous mélangez les types. C'est souvent une source de bugs.

console.log(1 + "1");     // "11" (String)
console.log("5" - 2);     // 3 (Number)
console.log(null + 1);    // 1
console.log(undefined + 1); // NaN
console.log("b" + "a" + + "a" + "a"); // "baNaNa" (Un classique)

Solution : Convertissez manuellement avec Number(), String(), Boolean().

3. Truthy et Falsy

Dans une condition if(), tout est évalué comme vrai ou faux. Les seules valeurs "Falsy" (qui valent false) sont : false, 0, "" (chaîne vide), null, undefined, NaN. Tout le reste (y compris [] et {}) est "Truthy".

3. Les Closures (Fermetures)

Une closure est une fonction qui "se souvient" de son environnement de création, même si celui-ci a disparu de la mémoire.

function usineACompteur() {
  let count = 0; // Variable privée
  return {
    incrementer: () => count++,
    lireValeur: () => count
  };
}
const compteur1 = usineACompteur();
compteur1.incrementer();
compteur1.incrementer();
console.log(compteur1.lireValeur()); // 2

Pourquoi c'est vital ? C'est le principe même de React (les Hooks gardent la mémoire entre les rendus) et de la programmation asynchrone.

1. Le trio magique (Map, Filter, Reduce)

Ces méthodes ne modifient jamais le tableau d'origine (Immutabilité), elles retournent un nouveau tableau.

const produits = [
  { nom: "PC", prix: 1000, stock: true },
  { nom: "Souris", prix: 50, stock: false },
  { nom: "Ecran", prix: 300, stock: true }
];

// Filtrer les produits en stock
const enStock = produits.filter(p => p.stock);

// Récupérer les noms
const noms = enStock.map(p => p.nom);

// Calculer le prix total
const total = produits.reduce((acc, p) => acc + p.prix, 0);

2. Copie par référence vs Copie par valeur

Les objets et tableaux sont copiés par référence. Si vous faites const a = {x:1}; const b = a;, modifier b modifiera a. C'est l'erreur n°1 des débutants en React.

// Solution : Le Spread Operator (...)
const a = { x: 1 };
const b = { ...a, y: 2 }; // Copie superficielle (Shallow copy)

// Pour les tableaux
const arr1 = [1, 2];
const arr2 = [...arr1, 3];

3. Méthodes utiles : sort, find, some, every

const nums = [10, 5, 8, 1];
nums.sort((a, b) => a - b); // Trie par ordre croissant
const trouve = nums.find(n => n === 8); // Retourne 8
const aDesNegatifs = nums.some(n => n < 0); // false
const tousPositifs = nums.every(n => n > 0); // true

    1. L'Event Loop expliqué simplement

    JS lit le code ligne par ligne. S'il tombe sur un setTimeout ou un fetch, il ne s'arrête pas. Il délègue ça au navigateur, continue de lire le reste, et quand la tâche de fond est finie, elle est placée dans une file d'attente. L'Event Loop vérifie si la pile (Call Stack) est vide, et si oui, il exécute la file d'attente.

    console.log("1");
setTimeout(() => console.log("2"), 0);
console.log("3");
// Affiche : 1, 3, 2

    Même avec 0 milliseconde, le setTimeout est asynchrone. Il passe après tout le code synchrone.

    2. Les Promesses en profondeur

    Une promesse est un objet avec 3 états (Pending, Fulfilled, Rejected). On la crée rarement soi-même, on consomme surtout celles des autres (ex: fetch).

    const promesse = fetch('https://api.com');

promesse
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error(error))
  .finally(() => console.log("Terminé"));

    3. Async / Await : La propreté

    C'est juste du sucre syntaxique par-dessus les promesses. Mais c'est beaucoup plus lisible.

    async function charger() {
  try {
    const reponse = await fetch('https://api.com');
    if (!reponse.ok) throw new Error("Erreur réseau");
    const data = await reponse.json();
    return data;
  } catch (e) {
    console.error(e);
  }
}
    Conseil de Senior

    Si vous avez plusieurs requêtes indépendantes à faire, ne les faites pas en série avec await (c'est lent). Faites Promise.all([fetch(url1), fetch(url2)]) pour les lancer en parallèle.

    Fetch remplace l'ancien XMLHttpRequest. Il retourne une promesse.

    async function getData() {
  const res = await fetch('https://jsonplaceholder.typicode.com/posts');
  const data = await res.json(); // Convertit le texte JSON en objet JS

    2. Envoyer des données (POST)

    async function postData(nouvelArticle) {
  const res = await fetch('https://api.com/posts', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': 'Bearer VOTRE_TOKEN'
    },
    body: JSON.stringify(nouvelArticle)
  });
  return res.json();
}
    Conseil de Senior

    La méthode fetch ne lève PAS d'erreur si le serveur répond 404 ou 500. Elle ne lève une erreur que si la requête réseau échoue (ex: pas d'internet). Vous devez TOUJOURS vérifier res.ok manuellement.

    Le projet : Application Météo & Actualités

    Vous allez construire une application qui consomme des APIs, manipule le DOM, utilise le localStorage et gère des états.

    Fonctionnalités :

    • Recherche de ville : Un input permet de chercher une ville.
    • API Météo : Utilisez l'API gratuite open-meteo.com pour récupérer la température et la condition actuelle.
    • Gestion de l'état UI : Affichez un "Spinner" (loader) pendant le chargement, et un message d'erreur si la ville n'existe pas.
    • Favoris : Un bouton "Ajouter aux favoris" qui sauvegarde la ville dans le localStorage.
    • Affichage des favoris : Au chargement de la page, lisez le localStorage et affichez la liste des villes favorites. Au clic sur une ville favorite, relancez la recherche météo.

    Architecture attendue (Sans Framework) :

    • Un fichier api.js (module) qui gère les appels fetch.
    • Un fichier storage.js (module) pour gérer le localStorage.
    • Un fichier ui.js (module) pour manipuler le DOM.
    • Un fichier main.js qui assemble le tout et gère les événements.
    Méthodologie

    C'est un projet de 2 semaines. Ne cherchez pas à tout faire le premier jour. Commencez par l'appel API avec un console.log. Puis l'affichage simple. Puis le loader. Puis les favoris. Gérez le code asynchrone avec async/await et try/catch.
