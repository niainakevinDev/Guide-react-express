Fondations des Réseaux

L'infrastructure invisible qui relie le monde. Maîtrisez l'adressage, le routage, les protocoles et la sécurité. Ce module vous prépare à administrer n'importe quel réseau.

1. Pourquoi diviser la communication en couches ?

Imaginez que vous construisez une maison. Vous ne demandez pas au fabricant de briques de s'occuper de la plomberie, ni au plombier de faire l'électricité. Chacun a son rôle spécialisé. C'est exactement le principe du modèle en couches (Layer Model) en réseau.

Sans ce modèle, un développeur web devrait connaître le voltage exact des câbles en cuivre pour afficher un site. Grâce à lui, chaque expert peut se concentrer sur sa partie.

2. Le Modèle OSI (7 couches théoriques)

Créé par l'ISO, c'est le modèle de référence pour comprendre la théorie. On le lit de bas en haut.

  • Couche 1 (Physique) : C'est le monde réel. Les câbles Ethernet, les ondes radio du WiFi, la lumière dans la fibre optique. On y parle en bits (0 et 1).
  • Couche 2 (Liaison de Données) : Elle s'occupe de la communication locale, sur le même réseau. L'adresse utilisée est l'adresse MAC (Media Access Control), gravée physiquement sur la carte réseau. Le matériel principal est le Switch. Les données s'appellent des Trames.
  • Couche 3 (Réseau) : C'est le GPS d'Internet. On y trouve l'adresse IP. Le matériel principal est le Routeur. Les données s'appellent des Paquets.
  • Couche 4 (Transport) : Elle découpe le message en morceaux et s'assure qu'ils arrivent à bon port. On y trouve les protocoles TCP et UDP. Les données s'appellent des Segments.
  • Couche 5 (Session) : Elle gère l'ouverture, le maintien et la fermeture de la conversation (ex: une session de connexion à un serveur).
  • Couche 6 (Présentation) : Elle traduit les données pour que l'application puisse les lire (ex: UTF-8 pour les caractères) et les chiffre (SSL/TLS).
  • Couche 7 (Application) : C'est ce que l'utilisateur voit. HTTP (le web), DNS (les noms de domaine), SMTP (les emails).

3. Le Modèle TCP/IP (4 couches réelles)

En pratique, Internet utilise le modèle TCP/IP (aussi appelé DoD), qui condense les 7 couches OSI en 4. C'est celui qui régit réellement vos paquets.

  • Accès Réseau (fusion OSI 1 et 2)
  • Internet (OSI 3)
  • Transport (OSI 4)
  • Application (fusion OSI 5, 6 et 7)

4. L'Encapsulation (Le concept le plus important)

Quand vous envoyez un message WhatsApp, voici ce qui se passe :

  1. Couche 7 : Votre message "Salut" est créé.
  2. Couche 4 : Il est découpé en segments et on ajoute un en-tête avec le port de destination. (Segment)
  3. Couche 3 : On ajoute un en-tête avec l'IP de destination. (Paquet)
  4. Couche 2 : On ajoute un en-tête avec l'adresse MAC du routeur. (Trame)
  5. Couche 1 : Tout cela est transformé en ondes radio (WiFi) ou signaux électriques.

Le destinataire fait le chemin inverse : il ouvre les enveloppes une par une (Décapsulation).

Conseil de Senior

Quand vous dépannez un réseau, posez-vous la question : "À quelle couche se situe le problème ?". Pas de WiFi ? Couche 1. Pas d'IP ? Couche 3. Le site ne charge pas ? Couche 7. Cette méthode divise par 10 votre temps de diagnostic.

Exercice Pratique (Réflexion)

Si votre navigateur affiche "Site inaccessible" mais que vous êtes connecté au WiFi, quelle couche est probablement en cause ?
Réponse : La couche 7 (Application) si le serveur est en panne, ou la couche 3 (Réseau) si l'adresse IP est incorrecte.

1. Anatomie d'une IPv4

Une adresse IPv4 est un nombre de 32 bits, divisé en 4 octets (chacun de 0 à 255), séparés par des points. Ex: 192.168.1.10.

Elle est composée de deux parties :

  • La partie Réseau : identifie le réseau (ex: votre box).
  • La partie Hôte : identifie la machine dans ce réseau (ex: votre PC, votre téléphone).

2. Le Masque de Sous-réseau

Il indique où s'arrête la partie réseau et où commence la partie hôte. Ex: 255.255.255.0. En notation CIDR, on l'écrit /24 (car 24 bits sur 32 sont réservés au réseau).

CIDR Masque Nb d'adresses
/24 255.255.255.0 256 (254 utilisables)
/25 255.255.255.128 128 (126 utilisables)
/26 255.255.255.192 64 (62 utilisables)
/30 255.255.255.252 4 (2 utilisables)

Pourquoi 254 utilisables en /24 ? Car la première adresse (.0) est le réseau et la dernière (.255) est le broadcast (l'adresse pour crier "Hey tout le monde !").

3. Les Adresses Privées (RFC 1918)

Elles ne sont pas routables sur Internet. Votre box vous en attribue une. Elles sont réservées pour éviter la pénurie d'IPv4.

  • 10.0.0.0 à 10.255.255.255 (Classe A - Réseaux immenses)
  • 172.16.0.0 à 172.31.255.255 (Classe B - Réseaux moyens)
  • 192.168.0.0 à 192.168.255.255 (Classe C - Maison, bureaux)
Conseil de Senior

Retenez le 192.168.1.1. C'est l'adresse par défaut de 90% des box Internet (Livebox, Freebox, etc.). C'est là que vous vous connectez pour configurer votre réseau.

Exercice Pratique

Vous avez le réseau 192.168.10.0/24. Vous devez le découper en 4 sous-réseaux égaux. Quel masque devez-vous utiliser ?
Réponse : /26 (car 2^2 = 4, donc on emprunte 2 bits au masque /24). Les réseaux seront : .0, .64, .128, .192.

1. Le DHCP (Dynamic Host Configuration Protocol)

Quand vous vous connectez à un WiFi, votre appareil crie "Quelqu'un peut me donner une adresse IP ?". Le serveur DHCP (votre box) répond avec une IP, un masque, une passerelle et un serveur DNS.

Ce processus s'appelle DORA :

  • Discover : Le client cherche un serveur DHCP.
  • Offer : Le serveur propose une IP.
  • Request : Le client demande officiellement cette IP.
  • Acknowledge : Le serveur confirme.

2. Le DNS (Domain Name System)

Le DNS traduit un nom lisible par l'homme (google.com) en adresse IP (142.250.201.46). C'est une immense base de données distribuée à travers le monde.

Quand vous tapez google.com, votre appareil demande d'abord à votre box, qui demande au FAI, qui demande aux serveurs racine (les 13 "dieux" d'Internet), qui redirigent vers le serveur de Google.

3. Les types d'enregistrements DNS

  • A : Fait correspondre un nom à une IPv4 (le plus courant).
  • AAAA : Fait correspondre un nom à une IPv6.
  • CNAME : Un alias. Ex: www.monsite.com pointe vers monsite.com.
  • MX : Indique le serveur de messagerie (email).
  • TXT : Texte libre (souvent utilisé pour la sécurité anti-spam).
Conseil de Senior

Si vous n'avez pas Internet mais que vous êtes connecté au WiFi, le problème vient très probablement du DNS. Essayez de configurer manuellement le DNS de Cloudflare (1.1.1.1) ou de Google (8.8.8.8) sur votre appareil.

1. TCP vs UDP

La couche Transport a deux protocoles principaux qui ont des philosophies opposées :

  • TCP (Transmission Control Protocol) : C'est le protocole de la fiabilité. Il vérifie que chaque paquet arrive (avec des accusés de réception) et les remet dans l'ordre. Utilisé pour le Web, les emails, les téléchargements.
  • UDP (User Datagram Protocol) : C'est le protocole de la vitesse. Il envoie les données sans vérifier si elles arrivent. Si une image est perdue lors d'un appel vidéo, ce n'est pas grave, on veut juste que ça ne lag pas. Utilisé pour le streaming, les jeux vidéo, le DNS.

2. Les Ports (0 à 65535)

Une adresse IP identifie la maison. Un port identifie la porte (le service) dans cette maison. C'est ce qui permet à votre PC de gérer en même temps votre navigateur, votre jeu et votre musique sans que les données ne se mélangent.

Port Protocole Usage
20 / 21 FTP Transfert de fichiers
22 SSH Terminal à distance sécurisé
25 SMTP Envoi d'emails
53 DNS Résolution de noms
80 HTTP Web non sécurisé
443 HTTPS Web sécurisé (TLS)
3306 MySQL Base de données
Conseil de Senior

Les ports 0 à 1023 sont réservés au système (il faut être administrateur root pour les ouvrir). Les ports 1024 à 49151 sont pour les applications (votre serveur Express tourne généralement sur le 3000 ou 8080).

Exercice Pratique

Sur votre ordinateur, ouvrez un terminal. Tapez netstat -tulpn (Linux) ou netstat -ano (Windows). Quels ports sont en écoute (LISTEN) sur votre machine ?

1. Le protocole HTTP

Le client (navigateur) envoie une Requête, le serveur renvoie une Réponse. C'est un protocole "sans état" : le serveur oublie qui vous êtes entre deux requêtes (d'où l'utilisation de cookies pour se souvenir de vous).

Les méthodes HTTP :

  • GET : Lire une ressource (ex: afficher une page).
  • POST : Créer une ressource (ex: envoyer un formulaire).
  • PUT : Remplacer entièrement une ressource.
  • PATCH : Modifier partiellement une ressource.
  • DELETE : Supprimer une ressource.

2. Les Codes de Statut (Status Codes)

Ils indiquent le résultat de la requête. C'est le premier réflexe à avoir pour déboguer.

  • 2xx (Succès) : 200 OK, 201 Created.
  • 3xx (Redirection) : 301 Moved Permanently.
  • 4xx (Erreur Client) : 400 Bad Request (données invalides), 401 Unauthorized (non connecté), 403 Forbidden (connecté mais pas le droit), 404 Not Found (n'existe pas).
  • 5xx (Erreur Serveur) : 500 Internal Server Error (le code du serveur a planté).

3. HTTPS et le chiffrement

HTTP envoie les données en clair. Si un pirate intercepte le trafic (sniffing) sur un WiFi public, il peut lire vos mots de passe. HTTPS ajoute une couche de chiffrement (TLS) : même si le pirate intercepte, il ne voit que du charabia.

Conseil de Senior

Apprenez à utiliser la commande curl -I https://google.com. Elle vous montre uniquement les headers de réponse HTTP, ce qui est parfait pour vérifier si un serveur est en ligne ou pour déboguer une API.

1. Les Routeurs

Un routeur est un aiguilleur. Il connecte deux réseaux différents (ex: votre réseau local et Internet). Il possède une "table de routage" et regarde l'IP de destination du paquet pour savoir par quelle interface l'envoyer.

Votre box Internet fait ça entre votre réseau local et le réseau de votre FAI (Fournisseur d'Accès).

2. Le NAT (Network Address Translation)

C'est la magie qui permet à tous vos appareils (téléphone, PC, TV) d'utiliser Internet en même temps avec une seule adresse IP publique.

Votre box fait du NAT : elle remplace l'IP privée (ex: 192.168.1.10) par son IP publique dans les paquets sortants, et fait l'inverse quand les réponses reviennent.

3. Le protocole ARP

Sur un réseau local, les machines communiquent via leur adresse MAC (adresse physique de la carte réseau). ARP permet de trouver l'adresse MAC associée à une adresse IP. (Tapez arp -a dans un terminal pour voir la table ARP).

Exercice Pratique

Utilisez la commande traceroute google.com (Linux/Mac) ou tracert google.com (Windows). Vous verrez tous les routeurs (les "sauts") que votre paquet traverse pour atteindre Google.

1. Les Pare-feux (Firewalls)

Ils filtrent le trafic entrant et sortant selon des règles. Ils peuvent bloquer une IP spécifique ou un port non autorisé. C'est le videur de votre réseau.

2. Le VPN (Virtual Private Network)

Il crée un tunnel chiffré entre votre appareil et un serveur distant. Votre FAI voit que vous envoyez des données à ce serveur, mais ne peut pas voir ce qu'il y a dedans. Vous prenez également l'IP du serveur distant, ce qui masque votre localisation réelle.

3. Les attaques courantes

  • DDoS (Distributed Denial of Service) : Saturation d'un serveur avec des millions de fausses requêtes depuis des milliers de machines infectées (Botnet). Le serveur tombe.
  • Man-in-the-Middle (MitM) : Un hacker s'interpose entre vous et le routeur (souvent via un faux hotspot WiFi). Le HTTPS prévient cela car le hacker ne peut pas déchiffrer.
  • Sniffing : Écoute du trafic réseau. Sur un WiFi public non chiffré (HTTP), n'importe qui peut lire ce que vous faites.
  • Phishing (Hameçonnage) : Le pirate vous envoie un faux email pour vous faire cliquer sur un faux site et voler vos identifiants.
Conseil de Senior

Ne vous connectez jamais à des sites HTTP (sans le S) sur un WiFi public (gare, aéroport). Utilisez un VPN si vous devez manipuler des données sensibles. Et méfiez-vous des emails urgents, c'est la base du phishing.

Projet : Simulation de réseau d'entreprise

Utilisez un logiciel gratuit comme Cisco Packet Tracer ou GNS3 pour construire le réseau de la société "Midas Corp".

Cahier des charges :

  • Topologie : 1 Routeur central, 3 Switchs (Administration, IT, WiFi).
  • Sous-réseaux :
    • Administration : 192.168.10.0/24
    • IT : 192.168.20.0/24
    • WiFi (Invités) : 192.168.30.0/24
  • Services : Mettre en place un serveur DHCP sur le routeur pour distribuer les IP à chaque sous-réseau.
  • Routage : Configurer le routeur pour que le PC de l'Administration puisse pinguer le PC de l'IT.
  • Sécurité (ACL) : Créer une règle sur le routeur interdisant au réseau WiFi (Invités) d'accéder au réseau Administration.
  • Serveur Web : Placer un serveur Web dans le réseau IT et s'assurer qu'il est accessible depuis le réseau Administration via HTTP.
Méthodologie

Dessinez d'abord votre topologie sur papier. Notez les plages d'IP. Configurez d'abord les IPs de base, testez les pings locaux, puis configurez le routage entre les réseaux. Enfin, appliquez les règles de sécurité.
