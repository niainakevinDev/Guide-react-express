1. Pourquoi des couches ?

Pour éviter qu'un ingénieur réseau ait besoin de comprendre comment fonctionne un câble en cuivre pour coder un site web. Chaque couche a un rôle précis et ne se préoccupe pas de ce qui se passe au-dessus ou en dessous.

2. Le Modèle OSI (7 couches théoriques)

  • 1. Physique : Câbles, WiFi, signaux électriques (bits 0 et 1).
  • 2. Liaison de données : Adresses MAC, commutateurs (Switch). Trames (Frames).
  • 3. Réseau : Adresses IP, routeurs. Paquets (Packets).
  • 4. Transport : Fiabilité, découpage. Protocoles TCP et UDP. Segments.
  • 5. Session : Ouverture et fermeture des communications.
  • 6. Présentation : Formatage, chiffrement (SSL/TLS), compression.
  • 7. Application : Ce que voit l'utilisateur (HTTP, DNS, FTP).

3. Le Modèle TCP/IP (4 couches réelles)

C'est le modèle utilisé par Internet. Il fusionne les couches hautes.

  • Accès Réseau (OSI 1 et 2)
  • Internet (OSI 3)
  • Transport (OSI 4)
  • Application (OSI 5, 6 et 7)
Conseil de Senior

L'encapsulation est le concept clé : quand vous envoyez un message, il descend les couches OSI en ajoutant des en-têtes (headers) à chaque étape. Arrivé à la couche physique, c'est une longue suite de bits. Le destinataire fait le chemin inverse (décapsulation).

Exercice Pratique (Réflexion)

Si votre navigateur affiche "Site inaccessible" mais que vous êtes connecté au WiFi, quelle couche est probablement en cause ?
Réponse : La couche 7 (Application) si le serveur est en panne, ou la couche 3 (Réseau) si l'adresse IP est incorrecte.

1. Anatomie d'une IPv4

Une adresse IPv4 est un nombre de 32 bits, divisé en 4 octets (chacun de 0 à 255), séparés par des points. Ex: 192.168.1.10.

Elle est composée de deux parties : la partie Réseau (identique pour toutes les machines du même réseau) et la partie Hôte (unique pour chaque machine).

2. Le Masque de Sous-réseau

Il indique où s'arrête la partie réseau. Ex: 255.255.255.0. En notation CIDR, on l'écrit /24 (car 24 bits sur 32 sont réservés au réseau).

CIDR Masque Nb d'adresses
/24 255.255.255.0 256 (254 utilisables)
/25 255.255.255.128 128 (126 utilisables)
/26 255.255.255.192 64 (62 utilisables)
/30 255.255.255.252 4 (2 utilisables)

Pourquoi 254 utilisables en /24 ? Car la première adresse (.0) est le réseau et la dernière (.255) est le broadcast.

3. Les Adresses Privées (RFC 1918)

Elles ne sont pas routables sur Internet. Votre box vous en attribue une.

  • 10.0.0.0 à 10.255.255.255 (Classe A)
  • 172.16.0.0 à 172.31.255.255 (Classe B)
  • 192.168.0.0 à 192.168.255.255 (Classe C)
Exercice Pratique

Vous avez le réseau 192.168.10.0/24. Vous devez le découper en 4 sous-réseaux égaux. Quel masque devez-vous utiliser ?
Réponse : /26 (car 2^2 = 4, donc on emprunte 2 bits au masque /24). Les réseaux seront : .0, .64, .128, .192.

1. Le DHCP (Dynamic Host Configuration Protocol)

Quand vous vous connectez à un WiFi, votre appareil crie "Quelqu'un peut me donner une adresse IP ?". Le serveur DHCP (votre box) répond avec une IP, un masque, une passerelle et un serveur DNS.

Ce processus s'appelle DORA : Discover, Offer, Request, Acknowledge.

2. Le DNS (Domain Name System)

Le DNS traduit un nom lisible par l'homme (google.com) en adresse IP (142.250.201.46). C'est une immense base de données distribuée à travers le monde.

3. Les types d'enregistrements DNS

  • A : Fait correspondre un nom à une IPv4.
  • AAAA : Fait correspondre un nom à une IPv6.
  • CNAME : Un alias (ex: www.monsite.com pointe vers monsite.com).
  • MX : Indique le serveur de messagerie (email).
  • TXT : Texte libre (souvent utilisé pour la sécurité anti-spam).
Conseil de Senior

Si vous n'avez pas Internet mais que vous êtes connecté au WiFi, le problème vient très probablement du DNS. Essayez de configurer manuellement le DNS de Cloudflare (1.1.1.1) ou de Google (8.8.8.8) sur votre appareil.

1. TCP vs UDP

  • TCP (Transmission Control Protocol) : Fiable. Vérifie que les paquets arrivent et les remet dans l'ordre. Utilisé pour le Web, les emails, les fichiers. (Il y a un "Three-way handshake" : SYN, SYN-ACK, ACK).
  • UDP (User Datagram Protocol) : Rapide, mais sans garantie. Utilisé pour le streaming vidéo, les jeux vidéo (une image perdue n'est pas grave, on veut juste que ça aille vite).

2. Les Ports (0 à 65535)

Une adresse IP identifie la maison. Un port identifie la porte (le service) dans cette maison. Les ports 0 à 1023 sont réservés (Well-known ports).

Port Protocole Usage
20 / 21 FTP Transfert de fichiers
22 SSH Terminal à distance sécurisé
25 SMTP Envoi d'emails
53 DNS Résolution de noms
80 HTTP Web non sécurisé
443 HTTPS Web sécurisé (TLS)
3306 MySQL Base de données
Exercice Pratique

Sur votre ordinateur, ouvrez un terminal. Tapez netstat -tulpn (Linux) ou netstat -ano (Windows). Quels ports sont en écoute (LISTEN) sur votre machine ?

1. Le protocole HTTP

Le client (navigateur) envoie une Requête, le serveur renvoie une Réponse.

Les méthodes HTTP : GET (lire), POST (créer), PUT (remplacer), DELETE (supprimer).

2. Les Codes de Statut (Status Codes)

  • 200 OK : Tout va bien.
  • 301 Moved Permanently : Redirection.
  • 400 Bad Request : Le client a envoyé n'importe quoi.
  • 401 Unauthorized : Il faut se connecter.
  • 403 Forbidden : Connecté, mais pas le droit d'accéder.
  • 404 Not Found : La page n'existe pas.
  • 500 Internal Server Error : Le serveur a planté.

3. HTTPS et le chiffrement

HTTPS = HTTP + TLS. Avant d'envoyer la requête, le client et le serveur échangent des clés cryptographiques (Handshake TLS) pour chiffrer la communication. Personne entre les deux (FAI, hacker WiFi) ne peut lire le contenu.

Conseil de Senior

Apprenez à utiliser la commande curl -v https://google.com. Elle vous montre exactement la requête HTTP et les headers de réponse envoyés par le serveur. C'est l'outil parfait pour déboguer une API.

1. Les Routeurs

Un routeur connecte deux réseaux différents. Il possède une "table de routage" et regarde l'IP de destination du paquet pour savoir par où l'envoyer.

2. Le NAT (Network Address Translation)

Vous avez 5 appareils chez vous (téléphones, PC, TV) mais une seule adresse IP publique fournie par votre FAI. Comment font-ils pour tous accéder à Internet en même temps ?

Votre box fait du NAT : elle remplace l'IP privée (ex: 192.168.1.10) par son IP publique dans les paquets sortants, et fait l'inverse quand les réponses reviennent.

3. Le protocole ARP

Sur un réseau local, les machines communiquent via leur adresse MAC (adresse physique de la carte réseau). ARP permet de trouver l'adresse MAC associée à une adresse IP. (Tapez arp -a dans un terminal pour voir la table ARP).

Ouvrir le cours complet

1. Les Pare-feux (Firewalls)

Ils filtrent le trafic entrant et sortant selon des règles. Ils peuvent bloquer une IP spécifique ou un port non autorisé.

2. Le VPN (Virtual Private Network)

Il crée un tunnel chiffré entre votre appareil et un serveur distant. Votre FAI voit que vous envoyez des données à ce serveur, mais ne peut pas voir ce qu'il y a dedans (et vous prenez l'IP du serveur distant).

3. Les attaques courantes

  • DDoS (Distributed Denial of Service) : Saturation d'un serveur avec des millions de fausses requêtes.
  • Man-in-the-Middle (MitM) : Un hacker s'interpose entre vous et le routeur (souvent via un faux hotspot WiFi). Le HTTPS prévient cela.
  • Sniffing : Écoute du trafic réseau. Sur un WiFi public non chiffré (HTTP), n'importe qui peut lire vos mots de passe.
Conseil de Senior

Ne vous connectez jamais à des sites HTTP (sans le S) sur un WiFi public (gare, aéroport). Utilisez un VPN si vous devez manipuler des données sensibles.

Projet : Simulation de réseau d'entreprise

Utilisez un logiciel gratuit comme Cisco Packet Tracer ou GNS3 pour construire le réseau de la société "Midas Corp".

Cahier des charges :

  • Topologie : 1 Routeur central, 3 Switchs (Administration, IT, WiFi).
  • Sous-réseaux :
    • Administration : 192.168.10.0/24
    • IT : 192.168.20.0/24
    • WiFi (Invités) : 192.168.30.0/24
  • Services : Mettre en place un serveur DHCP sur le routeur pour distribuer les IP à chaque sous-réseau.

  • Sécurité (ACL) : Créer une règle sur le routeur interdisant au réseau WiFi (Invités) d'accéder au réseau Administration.
  • Serveur Web : Placer un serveur Web dans le réseau IT et s'assurer qu'il est accessible depuis le réseau Administration via HTTP.
Méthodologie

Dessinez d'abord votre topologie sur papier. Notez les plages d'IP. Configurez d'abord les IPs de base, testez les pings locaux, puis configurez le routage entre les réseaux. Enfin, appliquez les règles de sécurité.
