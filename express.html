Qu'est-ce qu'Express ?

Express est le framework web minimaliste pour Node.js. Il fournit :

  • Un système de routing (URL → handler)
  • Un système de middlewares (fonctions en chaîne)
  • Une API simple pour requêtes/réponses HTTP

C'est le framework Node.js le plus utilisé, la base de Nest.js, et l'équivalent backend le plus courant de React côté front.

📌 Express ne fait pas tout Pas d'ORM, pas d'auth, pas de validation, pas de WebSocket. Il faut ajouter Prisma/Sequelize, JWT, zod, socket.io, etc.

Installation

Créer un projet Express from scratch

mkdir mon-api && cd mon-api
npm init -y
npm install express

# Dépendances recommandées en prod
npm install helmet cors dotenv express-rate-limit zod

# Dev
npm install -D nodemon

Fichier server.js minimal

const express = require('express');
const app = express();

app.use(express.json());

app.get('/', (req, res) => {
  res.json({ message: 'API OK' });
});

const PORT = process.env.PORT || 3000;
app.listen(PORT, '0.0.0.0', () => {
  console.log(`http://localhost:${PORT}`);
});

Scripts recommandés dans package.json

{
  "type": "module",
  "scripts": {
    "dev": "nodemon server.js",
    "start": "node server.js"
  }
}

Le "type": "module" active les import/export ES modernes (au lieu de require).

✅ Express 5 (2024+) Express 5 gère nativement les async errors (plus besoin de express-async-errors). Vérifie ta version avec npm ls express.

Routing

Routes HTTP

import { Router } from 'express';
const router = Router();

router.get('/users', listUsers);       // GET    /users
router.get('/users/:id', getUser);     // GET    /users/42
router.post('/users', createUser);     // POST   /users
router.put('/users/:id', replaceUser); // PUT    /users/42
router.patch('/users/:id', updateUser);// PATCH  /users/42
router.delete('/users/:id', deleteUser);// DELETE /users/42

export default router;

Monter le router

import usersRouter from './routes/users.js';
app.use('/api/users', usersRouter);
// Résultat : /api/users/42, etc.

Paramètres

// URL : /users/42?verbose=true
router.get('/users/:id', (req, res) => {
  const { id } = req.params;         // "42"
  const { verbose } = req.query;      // "true" (toujours string)
  res.json({ id, verbose: verbose === 'true' });
});
⚠️ Toujours valider req.params, req.query et req.body sont non fiables. Valide systématiquement (zod, joi, express-validator) avant d'utiliser.

Middlewares

Un middleware est une fonction (req, res, next) => {} exécutée dans l'ordre de déclaration. C'est le concept central d'Express.

Ordre critique

// ✅ Ordre correct
app.use(helmet());                          // 1. sécurité
app.use(cors());                            // 2. CORS
app.use(express.json({ limit: '1mb' }));    // 3. parse body
app.use(requestLogger);                     // 4. log
app.use('/api', routes);                    // 5. routes
app.use(notFound);                          // 6. 404
app.use(errorHandler);                      // 7. erreurs (TOUJOURS en dernier)

Middleware custom

function requestLogger(req, res, next) {
  const start = Date.now();
  res.on('finish', () => {
    console.log(`${req.method} ${req.originalUrl} ${res.statusCode} ${Date.now() - start}ms`);
  });
  next();
}

Auth par JWT

import jwt from 'jsonwebtoken';

export function requireAuth(req, res, next) {
  const header = req.headers.authorization;
  if (!header?.startsWith('Bearer ')) {
    return res.status(401).json({ error: 'Token manquant' });
  }
  try {
    const payload = jwt.verify(header.slice(7), process.env.JWT_SECRET);
    req.user = payload;
    next();
  } catch {
    res.status(401).json({ error: 'Token invalide' });
  }
}

// Usage
router.get('/me', requireAuth, (req, res) => {
  res.json(req.user);
});

Gestion d'erreurs

Express reconnaît un middleware d'erreur à ses 4 paramètres : (err, req, res, next).

Classe d'erreur custom

export class HttpError extends Error {
  constructor(status, message, details) {
    super(message);
    this.status = status;
    this.details = details;
  }
}

Handler global

export function errorHandler(err, req, res, next) {
  const status = err.status || 500;
  const message = status === 500 ? 'Erreur interne' : err.message;

  // Log complet côté serveur, jamais côté client en prod
  if (status >= 500) console.error(err);

  res.status(status).json({
    error: message,
    ...(err.details && { details: err.details }),
  });
}

Utilisation

router.get('/users/:id', async (req, res, next) => {
  try {
    const user = await User.findById(req.params.id);
    if (!user) throw new HttpError(404, 'Utilisateur introuvable');
    res.json(user);
  } catch (err) {
    next(err); // délégué au handler global
  }
});
❌ Fuites d'info Ne renvoie jamais err.stack ou err.message brut d'une erreur 500 au client. C'est une mine d'or pour un attaquant (chemins, versions, requêtes SQL).

Architecture en couches

Un projet Express maintenable sépare les responsabilités. Le pattern routes → controller → service → repository est le standard professionnel.

src/
├── server.js          → démarre l'app
├── app.js             → configure Express (testable sans listen)
├── routes/
│   └── users.routes.js
├── controllers/       → req/res, validation, statut HTTP
│   └── users.controller.js
├── services/          → logique métier
│   └── users.service.js
├── repositories/      → accès données (DB)
│   └── users.repository.js
├── middlewares/
│   ├── auth.js
│   └── errorHandler.js
├── validators/
│   └── users.validator.js
└── config/
    └── db.js

Exemple concret

// routes/users.routes.js
import { Router } from 'express';
import * as ctrl from '../controllers/users.controller.js';
import { validate } from '../middlewares/validate.js';
import { createUserSchema } from '../validators/users.validator.js';
import { requireAuth } from '../middlewares/auth.js';

const router = Router();
router.get('/', requireAuth, ctrl.list);
router.post('/', requireAuth, validate(createUserSchema), ctrl.create);
export default router;
// controllers/users.controller.js
import * as service from '../services/users.service.js';

export async function list(req, res, next) {
  try {
    const users = await service.getAll();
    res.json(users);
  } catch (e) { next(e); }
}

export async function create(req, res, next) {
  try {
    const user = await service.create(req.body);
    res.status(201).json(user);
  } catch (e) { next(e); }
}
// services/users.service.js
import * as repo from '../repositories/users.repository.js';
import { HttpError } from '../middlewares/errorHandler.js';

export async function getAll() {
  return repo.findAll();
}

export async function create(data) {
  const exists = await repo.findByEmail(data.email);
  if (exists) throw new HttpError(409, 'Email déjà utilisé');
  return repo.insert(data);
}

Sécurité

Checklist minimale (OWASP)

  • Helmet : headers HTTP sécurisés
  • CORS : configuré explicitement (pas * en prod)
  • Rate limiting : anti brute-force, anti-DDoS léger
  • Validation : zod/joi sur tous les inputs
  • Sanitisation SQL : requêtes paramétrées uniquement
  • Mots de passe : bcrypt/argon2, jamais en clair
  • Secrets : variables d'environnement (.env), jamais dans le code
  • HTTPS : obligatoire en prod
  • Body limit : express.json({ limit: '1mb' }) contre les gros payloads
  • Dépendances : npm audit régulier

Exemple de config sécurisée

import express from 'express';
import helmet from 'helmet';
import cors from 'cors';
import rateLimit from 'express-rate-limit';

const app = express();

app.use(helmet());
app.use(cors({
  origin: process.env.CORS_ORIGIN?.split(',') || 'http://localhost:5173',
  credentials: true,
}));
app.use(express.json({ limit: '1mb' }));
app.use(rateLimit({
  windowMs: 15 * 60 * 1000,
  max: 100,
}));
❌ Erreurs à ne jamais commettre
  • app.use(cors()) en prod sans restriction
  • Concaténer des requêtes SQL : "SELECT * WHERE id=" + id
  • Stocker des tokens dans localStorage côté front (XSS) → préférer cookies HttpOnly
  • Committer un .env sur GitHub
  • Retourner password dans les réponses JSON

Bonnes pratiques senior

1. Séparer app.js et server.js

app.js exporte l'app Express (testable avec supertest), server.js fait le listen.

2. Validation systématique

import { z } from 'zod';

const createUserSchema = z.object({
  email: z.string().email(),
  name: z.string().min(2).max(50),
  age: z.number().int().positive().optional(),
});

// middleware/validate.js
export const validate = (schema) => (req, res, next) => {
  const result = schema.safeParse(req.body);
  if (!result.success) {
    return res.status(400).json({ error: result.error.flatten() });
  }
  req.body = result.data; // données propres et typées
  next();
};

3. Variables d'environnement

# .env (JAMAIS commité)
DATABASE_URL=postgres://...
JWT_SECRET=...
PORT=3000

# .env.example (COMMITÉ, sans valeurs réelles)
DATABASE_URL=
JWT_SECRET=
PORT=3000

Au démarrage, valide que les variables critiques existent (zod sur process.env).

4. Logging structuré

import pino from 'pino';
const logger = pino({ level: process.env.LOG_LEVEL || 'info' });
logger.info({ userId, route }, 'utilisateur connecté');

Jamais console.log en prod. Pino / Winston pour du JSON loggé.

5. Codes HTTP corrects

CodeUsage
200OK (GET, PUT/PATCH réussis)
201Créé (POST réussi)
204Pas de contenu (DELETE réussi)
400Requête invalide (validation)
401Non authentifié (pas de token)
403Authentifié mais pas autorisé
404Ressource introuvable
409Conflit (email déjà pris)
422Entité non traitable (sémantique)
429Trop de requêtes (rate limit)
500Erreur serveur

6. Pagination

router.get('/users', async (req, res) => {
  const page = Math.max(1, parseInt(req.query.page) || 1);
  const limit = Math.min(100, parseInt(req.query.limit) || 20);
  const offset = (page - 1) * limit;

  const [items, total] = await Promise.all([
    repo.find({ limit, offset }),
    repo.count(),
  ]);

  res.json({
    items,
    pagination: { page, limit, total, pages: Math.ceil(total / limit) },
  });
});

Ne jamais renvoyer une liste non paginée en prod.

7. Tests avec supertest

import request from 'supertest';
import app from '../app.js';

test('GET /api/users retourne 200', async () => {
  const res = await request(app).get('/api/users');
  expect(res.status).toBe(200);
  expect(Array.isArray(res.body.items)).toBe(true);
});

8. Graceful shutdown

const server = app.listen(PORT);
process.on('SIGTERM', () => {
  server.close(() => {
    db.disconnect();
    process.exit(0);
  });
});

Avantages & limites honnêtes

✅ Avantages

  • Minimaliste : apprends vite, comprends tout ce qui se passe
  • Écosystème mature : tout existe en middleware (helmet, cors, morgan…)
  • Node.js : même langage front/back, async non-bloquant, très performant en I/O
  • Flexibilité totale : aucune opinion imposée, tu structures comme tu veux
  • Embauche : compétence très demandée, base de Nest.js
  • Communauté : réponses à toutes les questions existent déjà

❌ Limites

  • Trop minimaliste : aucune structure imposée → projets bordéliques si l'équipe n'est pas rigoureuse
  • Pas de TypeScript natif : Express est historiquement JS, l'intégration TS demande un peu de setup
  • Callbacks / middleware chain : moins élégant que les décorateurs de Nest.js
  • Performance : bonne mais battue par Fastify (benchmarks json)
  • Sécurité à la charge du dev : rien n'est sécurisé par défaut
  • Features répétitives : auth, validation, upload… à chaque projet, sauf si tu as un boilerplate
🎯 Verdict senior Express reste excellent pour des APIs simples à moyennes avec une équipe disciplinée. Pour un gros projet, Nest.js apporte structure et TS natif. Pour la performance pure, Fastify. Pour du full-stack TS, Next.js + Route Handlers ou tRPC.
