1. Initialisation

Node.js permet d'exécuter du JavaScript côté serveur. Express est le framework le plus populaire pour créer des APIs avec Node.

mkdir mon-api && cd mon-api
npm init -y
npm install express

2. Le serveur de base

const express = require('express');
const app = express();

app.get('/', (req, res) => {
  res.send('Hello depuis le serveur !');
});

app.listen(3000, () => {
  console.log('Serveur démarré sur http://localhost:3000');
});
Exercice Pratique

Lancez ce serveur. Dans votre navigateur, allez sur http://localhost:3000. Ajoutez ensuite une route /api/status qui retourne un objet JSON { "status": "ok" }.

1. Les verbes HTTP

  • GET : Récupérer des données.
  • POST : Créer une ressource.
  • PUT / PATCH : Modifier une ressource.
  • DELETE : Supprimer une ressource.

2. Les Middlewares

Un middleware est une fonction qui s'exécute entre la requête et la réponse. Il peut modifier la requête, la réponse, ou bloquer l'accès.

// Middleware de log
app.use((req, res, next) => {
  console.log(`[${req.method}] ${req.url}`);
  next(); // Passe au middleware suivant ou à la route
});
Conseil de Senior

L'ordre des middlewares est crucial. Si vous placez un middleware d'authentification après vos routes, il ne servira à rien car les routes auront déjà répondu.

Exercice Pratique

Créez un middleware qui vérifie si l'URL contient /admin. Si oui, renvoyez une erreur 403 (Accès refusé). Sinon, laissez passer avec next().

1. Qu'est-ce que MongoDB ?

C'est une base de données NoSQL qui stocke les données sous forme de documents JSON (appelés BSON). On utilise généralement la librairie mongoose pour interagir avec.

npm install mongoose

2. Créer un Modèle

const mongoose = require('mongoose');

const userSchema = new mongoose.Schema({
  nom: { type: String, required: true },
  email: { type: String, required: true, unique: true }
});

const User = mongoose.model('User', userSchema);
Exercice Pratique

Créez un modèle Article avec un titre, un contenu et une date. Faites une route POST pour créer un article et une route GET pour lister tous les articles.

1. Gestion des erreurs globales

Express a un middleware spécial pour les erreurs (avec 4 arguments). Il doit être placé tout à la fin de votre fichier.

app.use((err, req, res, next) => {
  console.error(err.stack);
  res.status(500).json({ error: 'Une erreur serveur est survenue' });
});

2. Validation avec Zod

Ne faites jamais confiance aux données envoyées par l'utilisateur.

const { z } = require('zod');
const schema = z.object({
  email: z.string().email(),
  age: z.number().min(18)
});

const result = schema.safeParse(req.body);
if (!result.success) {
  return res.status(400).json(result.error);
}

2. Le JSON Web Token (JWT)

Le JWT est un jeton que le serveur donne au client après le login. Le client l'envoie ensuite dans les headers pour prouver son identité.

const jwt = require('jsonwebtoken');
const token = jwt.sign({ userId: user.id }, 'SECRET_KEY', { expiresIn: '1h' });
Conseil de Senior

Ne mettez jamais de données sensibles dans le payload du JWT (il est décodable par n'importe qui). Mettez uniquement l'ID de l'utilisateur.

Le pattern MVC / Controller-Service

Si vous mettez tout dans server.js, votre code deviendra impossible à maintenir.

  • Routes : Définissent les URLs et les méthodes HTTP.
  • Controllers : Gèrent la requête (req) et la réponse (res).
  • Services : Contiennent la logique métier (ex: calculer une réduction).
  • Repositories : Gèrent l'accès à la base de données.

Exemple de Controller

// controllers/userController.js
exports.getUsers = async (req, res) => {
  const users = await User.find();
  res.json(users);
};

2. Sécurité avec Helmet & CORS

Helmet sécurise vos headers HTTP. CORS permet à votre frontend React (sur un autre port) de communiquer avec Express.

const helmet = require('helmet');
const cors = require('cors');

app.use(helmet());
app.use(cors());

Le projet : API de Blog

Vous allez construire le backend complet d'un site de blog.

Fonctionnalités :

  • Utilisateurs : Inscription (hash mot de passe), Login (retourne un JWT).
  • Articles : CRUD complet (Créer, Lire, Modifier, Supprimer).

  • Base de données : MongoDB pour stocker les utilisateurs et les articles.
  • Validation : Vérifier que le titre de l'article fait au moins 5 caractères.
Méthodologie

Testez votre API avec Postman ou Insomnia au fur et à mesure. Ne codez pas toutes les routes d'un coup. Faites l'authentification d'abord, testez-la, puis passez aux articles.
